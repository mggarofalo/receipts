# Receipt-entry description and product suggestions

Receipt entry has two distinct matching paths:

- Description autocomplete searches previous receipt descriptions and templates using PostgreSQL trigram similarity, optionally reranked with a local ONNX embedding. Results must also share an item-bearing word or typing prefix (or be an exact description); matching only package numbers, units or generic modifiers is not enough. Choosing a previous description replaces the input text. The score is a search ranking, not a calibrated probability. Results for a previous debounced input are never shown or selectable while the text has changed. The same list can also offer a supported normalized product: explicitly choosing it keeps the receipt text unchanged and records a one-purchase choice using the server-issued source fingerprint and product revision.
- The optional product chooser provides an expanded way to associate a purchase with a normalized product. It keeps the receipt description as entered. Exact names, approved description examples, and conservative whole-word product matches can be offered; package numbers, units and mere substrings alone are not product evidence. Two multiword names require at least two shared meaningful words. A whole product word may match a generic one-word target. A nearest semantic neighbour is also offered on its own when its cosine similarity reaches `ReceiptSuggestionEvidence.SemanticFloor` (0.80, measured in [catalog shortlist recall](normalization-evaluation/catalog-recall.md)). It is labelled "Similar meaning" and ranks after every suggestion with exact, approved or whole-word evidence; the inline description list shows at most two such rows. If the embedding model is unavailable or its queue is full, suggestions fall back to the other evidence. Suggestions require an explicit choice; no match is an ordinary result, and users can search, create a name, exclude, or continue without choosing.

Product lookup and historical description autocomplete do not invoke Jev or ChatGPT. Jev is used separately for optional category assistance; the ChatGPT connection supports separately requested normalization workflows. Connecting either service does not make these local entry suggestions an AI judgment. The chooser is available on demand in a dialog so it does not shift entry fields or force review for each item.

The synthetic fixture `tests/Fixtures/receipt-suggestion-quality.synthetic.json` records examples and counterexamples, including unrelated products that share packaging text. It is a regression corpus, not an estimate of production-wide accuracy. The conservative word rule intentionally misses some abbreviations and synonyms; the semantic floor recovers some of them and will occasionally admit a similar but different product. Suggestion retrieval ranks lexical candidates in one query by how many source words a name contains as whole words (a word found only inside a longer word counts for nothing), then by trigram similarity, and reads at most 200 of them; each channel contributes at most 20 and retrieval returns at most 20; full catalog search and approved exact-source rules remain available. It does not establish product identity or prove that every shared word indicates the same product. Never treat its scores or retrieval channels as confidence or automatically overwrite a receipt. The semantic similarity is never shown or returned by the API.
